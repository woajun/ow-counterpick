# 오버워치 카운터픽

적 팀 조합을 고르면 유리한 스왑 후보와 피해야 할 픽을 보여 주는 도구.
게임 중에 알트탭으로 넘어와서 몇 초 안에 쓰는 것을 전제로 만들었다 —
로그인이 없고, 홈 화면에서 바로 고르고 바로 초기화된다.

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # dist/
npm run preview
```

## 화면

| 경로 | 화면 |
| --- | --- |
| `/` | 추천 — 적 조합을 고르면 스왑 후보가 나온다 |
| `/table` | 상성표 — 영웅 전체를 행렬로 편 것 |

`/table` 은 `matchups.ts` 를 그대로 펴서 보여 준다. 가로줄이 내 픽, 세로줄이
적 픽이고 칸 값이 추천 점수에 얹히는 숫자 그대로다. 53 × 53 이라 십자선과
읽어 주는 줄을 붙였다. 빈 칸은 아직 안 적혔거나 중립이라는 뜻이다.

`BrowserRouter` 라 정적 호스팅에 올릴 때는 `/table` 도 `index.html` 로
돌려주도록 서버에 rewrite 을 걸어야 한다. `vite dev` 와 `vite preview` 는
기본으로 해 준다.

## 상성 데이터 고치는 곳

`src/data/matchups.ts` 하나다. 영웅 하나가 적으로 나왔을 때 내 쪽 픽마다
몇 점인지 적는다.

| | | |
| --- | --- | --- |
| `+3` 매우 유리 | `+2` 유리 | `+1` 약간 유리 |
| `−3` 매우 불리 | `−2` 불리 | `−1` 약간 불리 |

```ts
pharah: {
  ana: 3, ashe: 3, cassidy: 3, ..., dva: 2, ..., winston: 1,
  reinhardt: -2, ..., brigitte: -3,
},
```

`0`(중립 · 유동적)은 적지 않는다. 안 적힌 짝과 뜻이 같아서 자리를 차지할
이유가 없다.

점수는 적 하나하나가 독립적으로 얹는 단순한 합이다. 시너지나 맵은 안 본다.
설명할 수 없는 가중치를 넣는 것보다, 왜 그 픽이 올라왔는지를 근거 칩으로
그대로 보여주는 쪽이 게임 중에 쓸모 있다고 봤다. 불리한 근거도 같이 보여
준다 — 점수가 왜 깎였는지 안 보이면 "피해야 할 픽" 이 이유 없는 명단이 된다.

값은 나무위키 영웅 문서에서 옮긴 것이라 밸런스 패치마다 달라진다.
절대적인 기준이 아니라 스왑 후보를 좁히는 용도로 쓴다.

## 영웅 명단과 초상화

```bash
python3 scripts/sync_heroes.py
```

[OverFast API](https://overfast-api.tekrop.fr/) 에서 영웅 명단을 받아
`src/data/heroes.ts` 를 다시 쓰고, 초상화를 160px `webp` 로 줄여
`public/heroes/<id>.webp` 에 넣는다. 원본은 장당 150KB 인데 화면에서 제일 큰
자리가 74px 짜리 슬롯이라 그대로 둘 이유가 없다 — 53장 다 해서 420KB 다.

`heroes.ts` 는 손으로 고치지 않는다. 다음 실행에 날아간다. 좁은 타일에서
줄여 부르는 이름(`둠피`, `라인`, `위도우` …)은 스크립트 안 `SHORT` 표에 있다.

`matchups.ts` 는 스크립트가 건드리지 않는다. 새 영웅이 생기면 이름만 알려
주고 상성은 사람이 적는다 — 빈 항목을 자동으로 넣어 두면 타입 검사가 통과해
버려서, 목록에는 뜨는데 추천에는 영영 안 나오는 영웅이 조용히 생긴다.
미기입이 있으면 `/table` 위쪽에 그 수가 뜬다.

## 상성 데이터 가져오기

```bash
pip install playwright                      # 한 번만. 깔린 크롬을 그대로 쓴다
python3 scripts/scrape_matchups.py          # 53명 다 읽고 어긋난 곳을 알려 준다
python3 scripts/scrape_matchups.py --write  # matchups.ts 까지 다시 쓴다
```

나무위키 영웅 문서의 `상성` 절을 옮겨 적는다. 본문이 암호화된 덩어리로 오기
때문에 그냥 받으면 목차만 나온다 — 암호를 푸는 게 아니라 사람이 보는 것과 같은
화면을 브라우저로 띄워서 다 그려진 글자를 읽는다. `robots.txt` 가 `/w/` 를
허용하고 있고 1초에 한 장씩만 넘긴다. 받아 둔 문서는 `data/namu/pages/` 에
쌓이니 다시 돌려도 서버를 두 번 때리지 않는다.

나무위키의 등급을 그대로 점수로 옮긴다 — `매우 유리` `+3`, `유리` `+2`,
`약간 유리` `+1`, 그리고 불리 쪽도 대칭이다. `중립` 과 `유동적` 은 한쪽으로
기울지 않으니 안 적는다. 읽은 그대로의 등급 이름은 `data/namu/matchups.json`
에도 남는다 — 패치별로 비교하려면 그게 있어야 한다.

방향이 뒤집힌다는 것에 주의. 나무위키는 "캐서디 입장에서 라인하르트가 유리"
로 적고 이 프로젝트는 "라인하르트가 적일 때 캐서디가 좋다" 로 적는다.
스크립트가 뒤집어서 넣는다.

두 문서가 서로 자기가 유리하다고 적어 놓은 짝은 `data/namu/conflicts.md` 에
따로 모은다. 상성표에는 양쪽 주장이 그대로 들어가 있으니 한쪽으로 정하려면
`matchups.ts` 를 직접 고쳐야 한다. 2026-09-10 기준 37짝이다.

받아 둔 원본은 `data/namu/pages/` 에 80MB 쯤 쌓이므로 커밋하지 않는다.
정리한 결과인 `data/namu/matchups.json` 만 커밋한다.

| `src/data/heroes.ts` | 영웅 명단과 역할 |

| `src/lib/useSlashFocus.ts` | `/` 로 검색창 잡기 (상성표 화면) |
| `src/pages/` | 화면 두 벌 — 추천, 상성표 |
| `scripts/sync_heroes.py` | 영웅 명단·초상화 받아 오기 |
| `scripts/scrape_matchups.py` | 나무위키 상성 절 옮겨 적기 |

## 정해 둔 것

**어두운 화면 한 벌만 쓴다.** 게임에서 넘어오는데 밝은 페이지가 뜨면 눈이
부셔서 도구로 못 쓴다. 라이트 테마는 안 만든다.

**적 팀은 실제로 가능한 조합만 받는다.** 5v5 는 탱커 1 · 딜러 2 · 지원 2 로
고정이라 슬롯도 그 순서로 놓이고, 빈 자리에 아직 못 본 역할이 적힌다.
6v6 은 탱커만 최대 2명이고 딜러 · 지원은 합이 6이면 된다. 자리가 찬 역할은
영웅 목록에서 눌리지 않는다. 규칙은 `src/lib/roster.ts` 한 곳에 있다.

인원을 6에서 5로 줄이면 새 규칙에 안 맞는 자리가 잘린다 — 그냥 앞에서
다섯을 남기면 탱커 둘짜리 5v5 가 나온다.

**주로 하는 역할은 기억한다.** 추천 패널의 전체 / 탱커 / 딜러 / 지원 고른
것은 남겨 둔다 — 역할은 잘 안 바뀌는데 알트탭으로 넘어올 때마다 다시 고르게
하면 몇 초 안에 쓰는 도구가 아니게 된다. 한 역할만 볼 때는 자리가 남으니
4명 대신 8명까지 보여 준다.

**처음 열면 예시 조합이 깔려 있다.** 빈 껍데기는 무엇을 하는 도구인지
안 보여 준다. 손대는 순간 예시 표시가 내려가고, 예시 자체는 저장하지 않는다.

**추천 화면에는 검색이 없다.** 영웅이 53명이지만 역할별로 나뉘어 있고
초상화가 붙어 있어서 눈으로 집는 편이 빠르다. 검색은 상성표(`/table`)에만
둔다 — 거기는 53줄을 좁혀야 하는 화면이라 필요하다. <kbd>/</kbd> 로 바로
들어간다.

**초기화는 적 팀 머리줄에 있다.** 비우는 대상 바로 위다. 상단 바에 있으면
무엇을 되돌리는 버튼인지 안 보이고, 적 팀이 비어 있으면 눌리지 않는다.
