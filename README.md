# 오버워치 카운터픽

적 팀 조합을 고르면 유리한 스왑 후보와 피해야 할 픽을 보여 주는 도구.
게임 중에 알트탭으로 넘어와서 몇 초 안에 쓰는 것을 전제로 만들었다 —
로그인이 없고, 홈 화면에서 바로 고르고 바로 초기화된다.

**https://woajun.github.io/ow-counterpick/**

```bash
corepack enable
yarn install
yarn dev         # http://localhost:5173
yarn build       # dist/
yarn preview     # http://localhost:4173/ow-counterpick/
```

## 화면

| 경로 | 화면 |
| --- | --- |
| `/` | 추천 — 적 조합을 고르면 스왑 후보가 나온다 |
| `/table` | 상성표 — 영웅 전체를 행렬로 편 것. 상단 탭에는 안 띄운다 |

`/table` 은 상단 탭에 없다. 데이터를 검수할 때만 쓰는 화면이라 주소로 바로
들어간다. `matchups.ts` 를 그대로 펴서 보여 준다. 가로줄이 내 픽, 세로줄이
적 픽이고 칸 값이 추천 점수에 얹히는 숫자 그대로다. 53 × 53 이라 십자선과
읽어 주는 줄을 붙였다. 빈 칸은 아직 안 적혔거나 중립이라는 뜻이다.

## 배포

`main` 에 밀면 [GitHub Actions](.github/workflows/deploy.yml) 가 빌드해서
Pages 로 올린다. 리포 Settings → Pages → Source 를 **GitHub Actions** 로
한 번 바꿔 두면 그다음부터는 자동이다.

프로젝트 사이트라 주소 앞에 리포 이름이 붙는다. `vite.config.ts` 의 `base`,
`BrowserRouter` 의 `basename`, 초상화 경로가 다 거기에 맞춰져 있으니 리포
이름을 바꾸면 `base` 한 줄만 고치면 된다.

Pages 에는 서버 rewrite 이 없어서 `/table` 로 바로 들어오면 404 가 난다.
빌드 끝에 `index.html` 을 `404.html` 로 복사해 둔다 — Pages 가 모르는 경로에
그걸 내주는데 그게 곧 앱이라 화면이 그대로 뜬다.

## 상성 데이터 고치는 곳

`src/data/matchups.ts` 하나다. 영웅 하나가 적으로 나왔을 때 내 쪽 픽마다
몇 점인지 적는다.

| | | |
| --- | --- | --- |
| `+3` 매우 유리 | `+2` 유리 | `+1` 약간 유리 |
| `−3` 매우 불리 | `−2` 불리 | `−1` 약간 불리 |

```ts
pharah: {
  ana: 3, ashe: 3, cassidy: 3, ..., dva: 2, ..., winston: 1,
  reinhardt: -2, ..., brigitte: -3,
},
```

`0`(중립 · 유동적)은 적지 않는다. 안 적힌 짝과 뜻이 같아서 자리를 차지할
이유가 없다.

점수는 적 하나하나가 독립적으로 얹는 단순한 합이다. 시너지나 맵은 안 본다.
설명할 수 없는 가중치를 넣는 것보다, 왜 그 픽이 올라왔는지를 근거 칩으로
그대로 보여주는 쪽이 게임 중에 쓸모 있다고 봤다. 불리한 근거도 같이 보여
준다 — 점수가 왜 깎였는지 안 보이면 "피해야 할 픽" 이 이유 없는 명단이 된다.

값은 나무위키 영웅 문서에서 옮긴 것이라 밸런스 패치마다 달라진다.
절대적인 기준이 아니라 스왑 후보를 좁히는 용도로 쓴다.

## 영웅 명단과 초상화

```bash
python3 scripts/sync_heroes.py
```

[OverFast API](https://overfast-api.tekrop.fr/) 에서 영웅 명단을 받아
`src/data/heroes.ts` 를 다시 쓰고, 초상화를 160px `webp` 로 줄여
`public/heroes/<id>.webp` 에 넣는다. 원본은 장당 150KB 인데 화면에서 제일 큰
자리가 74px 짜리 슬롯이라 그대로 둘 이유가 없다 — 53장 다 해서 420KB 다.

`heroes.ts` 는 손으로 고치지 않는다. 다음 실행에 날아간다. 좁은 타일에서
줄여 부르는 이름(`둠피`, `라인`, `위도우` …)은 스크립트 안 `SHORT` 표에 있다.

이름은 전부 한글로 맞춰 둔다(`D.Va` → `디바`, `D.Mon` → `디몬`). 표시용 글꼴
Oswald 에 한글이 없어서 한글 이름은 IBM Plex 로 떨어지는데, 라틴 문자만
Oswald 로 그려지면 그 영웅 이름만 굵고 좁아 보인다.

`matchups.ts` 는 스크립트가 건드리지 않는다. 새 영웅이 생기면 이름만 알려
주고 상성은 사람이 적는다 — 빈 항목을 자동으로 넣어 두면 타입 검사가 통과해
버려서, 목록에는 뜨는데 추천에는 영영 안 나오는 영웅이 조용히 생긴다.
미기입이 있으면 `/table` 위쪽에 그 수가 뜬다.

## 상성 데이터 가져오기

```bash
pip install playwright                      # 한 번만. 깔린 크롬을 그대로 쓴다
python3 scripts/scrape_matchups.py          # 53명 다 읽고 어긋난 곳을 알려 준다
python3 scripts/scrape_matchups.py --write  # matchups.ts 까지 다시 쓴다
```

나무위키 영웅 문서의 `상성` 절을 옮겨 적는다. 본문이 암호화된 덩어리로 오기
때문에 그냥 받으면 목차만 나온다 — 암호를 푸는 게 아니라 사람이 보는 것과 같은
화면을 브라우저로 띄워서 다 그려진 글자를 읽는다. `robots.txt` 가 `/w/` 를
허용하고 있고 1초에 한 장씩만 넘긴다. 받아 둔 문서는 `data/namu/pages/` 에
쌓이니 다시 돌려도 서버를 두 번 때리지 않는다.

나무위키의 등급을 그대로 점수로 옮긴다 — `매우 유리` `+3`, `유리` `+2`,
`약간 유리` `+1`, 그리고 불리 쪽도 대칭이다. `중립` 과 `유동적` 은 한쪽으로
기울지 않으니 안 적는다. 읽은 그대로의 등급 이름은 `data/namu/matchups.json`
에도 남는다 — 패치별로 비교하려면 그게 있어야 한다.

방향이 뒤집힌다는 것에 주의. 나무위키는 "캐서디 입장에서 라인하르트가 유리"
로 적고 이 프로젝트는 "라인하르트가 적일 때 캐서디가 좋다" 로 적는다.
스크립트가 뒤집어서 넣는다.

두 문서가 서로 자기가 유리하다(또는 서로 불리하다)고 적어 놓은 짝이 있다.
애쉬 문서는 "메이 상대로 불리", 메이 문서도 "애쉬 상대로 불리"라고 적는 식이라
둘 다 자기가 진다는 말이 된다. 옮겨 적으면서 생긴 오류가 아니라 원본이 그렇게
되어 있는 것이다.

`data/namu/conflicts.md` 에 표로 모으고, `src/data/conflicts.ts` 로도 내보내서
상성표에서 그 칸 모서리에 빗금을 긋는다. 표시가 없으면 도구가 고장 난 것처럼
보인다 — 실제로 이 표시를 붙인 이유가 그거다. 2026-09-10 기준 37짝이다.

`src/data/namu.ts` 에는 영웅별 문서 제목이 들어간다. 이름이 겹치는 영웅은
`파라(오버워치)` 처럼 밀려 있어서, 화면에서 원본 문서로 링크를 걸려면 실제로
받아 온 제목을 알아야 한다. 53명 중 25명이 그렇다.

받아 둔 원본은 `data/namu/pages/` 에 80MB 쯤 쌓이므로 커밋하지 않는다.
정리한 결과인 `data/namu/matchups.json` 만 커밋한다.

## 정해 둔 것

**틀린 값은 여기서 안 고친다.** 상성표에서 칸을 짚으면 그 영웅의 나무위키
상성 절로 가는 링크가 뜬다. 이 도구는 옮겨 적은 사본이라 여기서 고쳐 봐야
원본은 그대로고, 원본을 고치면 그 문서를 보는 모두에게 반영된다. 대신 다음
수집 전까지는 이 표가 안 따라온다는 시차가 있다.

읽어 주는 줄은 표에서 마우스를 떼도 남는다. 사라지면 그 안의 링크를 누르러
가는 사이에 없어진다.

**좁은 화면에서는 자리가 찬 역할의 못 고르는 영웅을 감춘다.** 53명을 훑는
것 자체가 일이라, 5v5 에서 탱커를 하나 고르면 나머지 탱커는 어차피 못 고르니
남겨 둘 이유가 없다. 고른 영웅은 남아서 다시 눌러 뺄 수 있다. 넓은 화면에서는
자리가 남으니 흐리게만 하고 그대로 둔다.

**접힌 추천 줄에는 얼굴을 넣는다.** 게임에서 영웅은 이름보다 얼굴로 먼저
알아본다. 역할 색 테두리를 둘러서 탱커·딜러·지원이 한눈에 갈린다.

**좁은 화면에서는 적 팀이 상단 바 아래에 붙는다.** 영웅을 고르러 아래로
내려가면 지금까지 고른 적이 안 보인다. 붙여 두면 고르는 내내 조합이 보인다.
대신 자리를 계속 차지하니 영문 이름을 빼고 칸을 낮춰서 145px 을 122px 로
줄였다.

**좁은 화면에서는 추천이 아래에 붙는 시트가 된다.** 목록 위에 추천을 두면
영웅을 고를 때마다 추천이 커졌다 작아지면서 그 아래 목록이 통째로 밀린다.
손가락 밑에서 화면이 움직이고, 결과를 보려면 다시 위로 올라가야 한다. 시트로
떼어 내면 고르는 자리는 안 움직이고 결과는 그 자리에서 바뀐다. 접힌 채로도
역할별 1위는 보이니 대개 펼칠 일이 없다.

**어두운 화면 한 벌만 쓴다.** 게임에서 넘어오는데 밝은 페이지가 뜨면 눈이
부셔서 도구로 못 쓴다. 라이트 테마는 안 만든다.

**적 팀은 실제로 가능한 조합만 받는다.** 5v5 는 탱커 1 · 딜러 2 · 지원 2 로
고정이라 슬롯도 그 순서로 놓이고, 빈 자리에 아직 못 본 역할이 적힌다.
6v6 은 탱커만 최대 2명이고 딜러 · 지원은 합이 6이면 된다. 자리가 찬 역할은
영웅 목록에서 눌리지 않는다. 규칙은 `src/lib/roster.ts` 한 곳에 있다.

인원을 6에서 5로 줄이면 새 규칙에 안 맞는 자리가 잘린다 — 그냥 앞에서
다섯을 남기면 탱커 둘짜리 5v5 가 나온다.

**주로 하는 역할은 기억한다.** 추천 패널의 전체 / 탱커 / 딜러 / 지원 고른
것은 남겨 둔다 — 역할은 잘 안 바뀌는데 알트탭으로 넘어올 때마다 다시 고르게
하면 몇 초 안에 쓰는 도구가 아니게 된다. 한 역할만 볼 때는 자리가 남으니
4명 대신 8명까지 보여 준다.

**영웅 상성은 눌러서 펼친다.** 추천 줄을 누르거나 영웅 타일 우상단의 `i` 를
누르면 그 영웅이 적 전체를 상대로 어떤지 `+3` 부터 `−3` 까지, 영웅 53명을
빠짐없이 펴서 보여 준다. 묶음마다 탱커·딜러·지원 3열로 세워서 "이 등급에서
탱커는 뭐가 있나"를 세로로 훑을 수 있게 했다. 타일 자체는 고르는 버튼이라
`i` 를 따로 냈다 — 고르지 않고 보기만 하고 싶을 때가 있다.

역할 머리는 맨 위에 한 번만 둔다 — 등급 묶음마다 달면 일곱 번 반복된다.
원본 문서로 가는 나무위키 로고는 머리줄에 있다.

`0` 은 둘로 갈라 보여 준다. **중립이라 적어 둔 것**(594짝)은 판단이 있는
것이라 눈금 그대로 `+1` 과 `−1` 사이에 두고, **끝까지 빈 짝**(2짝)은 등급이
아니라 자료가 없는 것이라 맨 뒤로 뺀다. `matchups.ts` 에는 0 을 적지 않아서
그 구별이 사라지는데, `src/data/neutral.ts` 가 그걸 따로 들고 있다.

## 한쪽만 적힌 짝은 뒤집어 메운다

나무위키는 두 영웅 중 한쪽 문서에만 적어 두는 일이 잦다. `raw[a][b]` 가
비어 있어도 `raw[b][a]` 가 있으면 같은 짝에 대한 진술이다 — b 가 a 에게
유리하면 a 는 b 에게 그만큼 불리하다. 부호만 뒤집으면 된다.

이걸로 빈 짝 106개 중 104개가 메워졌다(81개는 점수, 23개는 중립). 끝까지
빈 짝은 2개뿐이다.

뒤집어 온 값은 `src/data/inferred.ts` 에 따로 표시해 둔다. 나중에 원본이
채워지면 덮어써야 하고, 한쪽 문서만 근거라서 무게가 다르다. 상성 모달에서는
테두리를 점선으로 그어 조용히 구별한다.

**빈 채로 시작한다.** 예시 조합을 깔아 두면 쓰기 전에 지우는 것이 첫 일이
된다. 적 슬롯에 역할 이름이 적혀 있어서 빈 화면이어도 무엇을 하는 자리인지
보인다.

**추천 화면에는 검색이 없다.** 영웅이 53명이지만 역할별로 나뉘어 있고
초상화가 붙어 있어서 눈으로 집는 편이 빠르다. 검색은 상성표(`/table`)에만
둔다 — 거기는 53줄을 좁혀야 하는 화면이라 필요하다. <kbd>/</kbd> 로 바로
들어간다.

**초기화는 적 슬롯 줄 맨 앞에 있다.** 슬롯과 같은 높이로 서 있어서 무엇을
비우는 버튼인지 바로 보인다. 머리줄에 작게 달려 있을 때는 있는 줄도 몰랐다.
적 팀이 비어 있으면 눌리지 않는다.
